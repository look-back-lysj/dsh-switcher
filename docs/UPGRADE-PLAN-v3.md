## §1 用户痛点与目标

### 痛点（用户原话）
1. "功能没有分开做，备份恢复肯定是一个单独的功能"
2. "环境对话和切换是核心功能，可以快速对文件进行置换（前提是都进行了备份）"
3. "仓库功能意义不明，新手看不懂"
4. "备份功能直接在体检那里做就可以了，那里可以选择备份、查看有多少对话"

### 目标信息架构（3 页签）
```
[侧边导航]
  环境    → 体检 + 备份一体（扫描 → 看环境 → 一键备份）
  存档    → 快照列表 + 恢复（回到任意状态）
  切换    → 跨环境搬数据（A 环境 → B 环境）
```

## §2 模块一：环境页（体检 + 备份合并）

### 现状问题
- 体检和备份分两个页签，用户要在两边来回切换
- 备份页有独立的路径输入框（虽然已折叠到高级选项），概念上仍然分离

### 新设计
**页面标题**：我的环境

**布局**（自上而下）：
```
[统计卡片行]（保留现有 4 个指标 + 数字滚动动画）

[环境列表]（保留现有列表，每行加"对话 N 个"徽章）
  每行右侧加：[备份] 按钮（单独备份这个环境）

[一键备份区]（页面底部固定或环境列表下方）
  "已识别 N 个环境，共 M 个对话"
  [备注输入框]
  [立即备份全部] 大按钮
  [高级选项 ▾]（路径、仅配置、校验）

[最近备份]（精简列表，最多 3 条）
  "刚刚 · 切换到 4.5 之前 · 3 环境 · 58.6 MB"
  [查看全部 →] 跳转到存档页
```

### 后端改动
- 新增 `backup_single_home(repo, home_path, note)` 命令：只备份指定环境（复用现有 `run_backup` 逻辑，过滤 homes）
- 现有 `backup` 命令保持全量备份

### 前端改动
- 删除 `view-backup` section，把备份 hero 区移到 `view-health` 底部
- 环境列表每行加"备份"按钮，调用 `backup_single_home`
- 备份成功动画保留，但改为在当前页内展示（不跳转）

## §3 模块二：存档页（快照列表 + 恢复）

### 现状问题
- 时光机和恢复分两个页签，概念重复
- "恢复"对新手来说是术语，"回到这个状态"才是人话

### 新设计
**页面标题**：我的存档

**布局**：
```
[顶部操作区]
  [把当前状态存为快照] 按钮（次要，因为环境页也能备份）
  [刷新列表]

[快照列表]（时光机现有卡片样式保留）
  每张卡片：备注（可双击改名）/ 时间 / 环境数 / 文件数 / 大小
  点击卡片展开详情面板

[详情面板]（选中快照后显示）
  - 包含哪些环境（列出路径和对话数）
  - [回到这个状态] 主按钮
  - [导出为 zip] 次按钮
  - [删除此快照] 危险按钮（小，红色，需确认）

[高级操作 ▾]（折叠区，原"恢复"页能力）
  - 按会话恢复（找会话场景）
  - 按文件类型恢复（只恢复配置/只恢复技能）
  - 覆盖策略选择
```

### 后端改动
- 新增 `delete_snapshot(repo, snapshot_id)` 命令：删除 `snapshots/<id>/` 目录，并清理 `files/` 中不再被引用的文件（引用计数，简单版：只删 snapshots 目录，files 保留）

### 前端改动
- 删除 `view-timemachine` 和 `view-restore` section，合并为 `view-archive`
- 快照列表、详情面板、回滚逻辑保留（从 timemachine 迁移）
- 原 restore 页的"恢复范围/覆盖策略/来源目标"折叠进高级操作区

## §4 模块三：切换页（核心新功能）★

### 功能定义
> 把 A 环境的对话、技能、配置等"搬"到 B 环境，让 B 环境拥有 A 的内容。
> 前提：B 环境已有备份（或自动先备份 B）。

### 用户故事
- "我在用 v4lite，但我想继续主版本里的某个对话" → 把主版本切换到 v4lite
- "我装了个新的民间版，想试试但不想从头开始" → 把旧环境切换到新环境
- "我想把 A 的技能和 B 的对话合并" → v3.1 功能（本次不做）

### 交互设计（卡片拖拽）

**页面标题**：切换环境

**布局**：
```
[说明卡片]
  "把左边环境的对话、技能、配置搬到右边环境。
   搬之前会自动备份右边环境，不会丢东西。"

[拖拽区]
  ┌─────────────┐     ┌─────────────┐
  │  来源环境    │     │  目标环境    │
  │  (拖我)      │ ──► │  (放这里)    │
  │             │     │             │
  │  主版本      │     │  v4lite     │
  │  14 对话     │     │  18 对话     │
  │  2.3 MB     │     │  1.8 MB     │
  └─────────────┘     └─────────────┘

[下方：环境列表]
  每个环境一张卡片，可拖拽到上方"来源"或"目标"槽位
  卡片内容：名称 / 对话数 / 大小 / 健康徽章 / [选择] 按钮（备选：点击代替拖拽）

[切换选项]（选中来源和目标后显示）
  ☑ 对话记录（sessions）
  ☑ 技能（skills）
  ☑ 配置档案（profiles/settings）
  ☐ 记忆（memories）
  ☐ 预设（.agent-presets）

[开始切换] 大按钮（主色，选中来源和目标后才可用）
```

### 拖拽交互细节
- 环境卡片：`draggable="true"`，拖拽时半透明 + 阴影
- 来源/目标槽位：`dragover` 时高亮边框，`drop` 时填充卡片内容
- 也支持点击卡片上的"设为目标"按钮（拖拽的备选方案）
- 来源和目标不能是同一个环境（校验 + 提示）

### 切换流程（后端）
```
1. 校验：来源和目标都已识别，且不是同一个
2. 自动备份目标环境（保险快照，备注："切换前自动保存"）
3. 从来源复制选中类型的文件到目标
   - 对话：复制 sessions/ 下对应目录（保留结构）
   - 技能：复制 skills/ 目录
   - 配置：复制 settings.yaml, profiles/ 等
   - 冲突：覆盖（因为已经备份了目标）
4. 生成切换报告：新建 N 个，覆盖 M 个，失败 K 个
5. 失败时自动回滚（复用现有 restore.rs 的事务逻辑）
```

### 后端新增命令
```rust
switch_environment(
    repo: String,           // 备份仓库路径
    source_home: String,    // 来源环境路径
    target_home: String,    // 目标环境路径
    include_sessions: bool,
    include_skills: bool,
    include_config: bool,
    include_memories: bool,
    include_presets: bool,
) -> Result<SwitchResult, String>

pub struct SwitchResult {
    pub backup_snapshot_id: String,  // 自动备份的快照 ID
    pub created: u32,
    pub overwritten: u32,
    pub skipped: u32,
    pub failed: Vec<String>,
}
```

### 前端改动
- 新增 `view-switch` section
- 环境卡片从 `state.homes` 渲染，支持拖拽和点击选择
- 切换前弹确认面板：列出来源、目标、将复制哪些类型、自动备份提示
- 切换中显示进度条（复用 backup 进度组件）
- 切换成功后显示结果卡片 + [去存档看看] 链接

## §5 模块四：删除"仓库"页

### 现状问题
- 仓库页包含：校验、导出/导入 zip、回滚日志、撤回覆盖
- 这些功能对新手来说太底层，且分散了注意力

### 迁移方案
| 原功能 | 去向 |
|---|---|
| 校验仓库 | 存档页 → 高级操作 ▾ |
| 导出 zip | 存档页 → 快照详情 → [导出为 zip] |
| 导入 zip | 存档页 → 顶部操作区 → [导入备份包]（次要按钮） |
| 回滚日志 | 存档页 → 高级操作 ▾ |
| 撤回覆盖 | 存档页 → 高级操作 ▾ |

### 前端改动
- 删除 `view-repository` section 和导航项
- 把上述功能按钮迁移到存档页的对应位置
- 保留所有后端命令不变

## §7 执行顺序

1. **合并环境页**：把备份功能移到体检页，删除独立备份页签
2. **合并存档页**：把时光机和恢复合并为存档页，删除恢复页签
3. **迁移仓库功能**：把仓库页功能分散到存档页，删除仓库页签
4. **新增切换页**：后端 `switch_environment` 命令 + 前端拖拽交互
5. **导航简化**：改为 3 个页签，文案精简
6. **测试**：单元测试 + e2e 回归 + 手动验证切换流程
7. **打包安装**：NSIS 打包，装到本机

## §10 风险与缓解

| 风险 | 缓解 |
|---|---|
| 拖拽交互在 WebView2 有兼容性问题 | 同时提供点击选择作为备选方案 |
| 切换时 DSH 正在运行导致文件占用 | 切换前检测 DSH 进程，提示用户先关闭 |
| 切换后 DSH 无法识别对话 | 切换完成后提示"请重启 DSH 查看" |
| 用户误删快照 | 删除快照需二次确认，且删除前提示"此操作不可撤销" |
