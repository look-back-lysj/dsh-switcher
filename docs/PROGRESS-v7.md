> 起因：同学机器（17155）的复盘报告《DSH-Vault迁移复盘》——12 次切换把 `.dsh` 里新产生的
> 对话反复抹掉（10 次日志全绿）。本轮逐条核实报告，修正真问题、澄清误判。

## v7 三项根治

1. **切换默认「合并模式」**：来源内容复制进目标，**绝不删除目标端独有内容**；
   同名以来源为准。workspace.json **结构化合并**（工作区按 path 对齐、sessionIds 取并集、
   archived 取并集、目标端原登记全保留）。旧的覆盖行为保留为需显式勾选的「替换模式」。
2. **找回对话**：切换页新增"找回对话/修复登记"面板，列出目标端的历史保险快照，
   一键把快照里**当前缺失的对话**找回来并自动登记（只增不删）。
3. **修复对话登记**：把磁盘上存在、workspace.json 未登记的对话补登记（含 projcache），
   让它们重新出现在侧栏。切换完成后也会**自动跑一次**。

## 给同学机器的恢复路径（装新包后）

1. 关闭 DSH → 打开 DSH Vault → 在「切换」页选好目标环境（.dsh）。
2. 「找回对话」面板会列出 12 份历史保险快照 → 对丢失会话所在的那次点**找回其中的对话**
   （比如 10-08 18:23 之前那份，可把被抹掉的会话找回并自动登记）。
3. 或直接用报告里导出的 Markdown 对照确认。
4. 之后再用切换：默认就是合并模式，不会再抹掉任何对话。
