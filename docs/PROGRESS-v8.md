## 0. 先说结论：哪些是真 bug、哪些是误判

| # | 复盘里的说法 | 核实结果 | 本轮处理 |
|---|---|---|---|
| 1 | 「还原」6 次全失败，报 `仓库文件路径不安全：…settings.yaml.imported` | **真 bug（P0）**：v5 把 blob 改成 `snapshots/<id>/files/` 布局后，`repo.rs` 的 `is_safe_repo_path` 仍只认 `blobs/`，导致**所有新备份**的预览恢复/执行恢复/仓库校验/导出全部被整包拒绝 | 已修 + 回归测试 |

| 3 | 「合并模式没保住目标端登记」 | **真 bug（P0）**：`copy_dir_merge` 对同名文件是覆盖；`storages/workspace.json` 先被来源覆盖，随后 `merge_workspace_json` 合并的是「来源自己」，等于没合并 | 已修：复制前留目标原件，复制后回写再合并 |
| 4 | 「只勾对话时，文件搬了但侧栏看不到」 | **真 bug（P0）**：workspace.json 的合并被写死在 `include_config` 分支里，只勾「对话记录」时根本不同步登记表 | 已修：只要涉及对话就必须同步登记表 |
| 5 | 「补登记抄 AIO 的表，AIO 没有的工作区永远补不上」 | 描述的是更早版本行为；v7 的 repair 已按 cwd 建工作区，但本轮又发现两处缺陷：① cwd 解析失败时静默跳过；② 写入的 `path` 没按官方 `realpath` 规范化，官方一次 mutate 就会把它过滤掉 | 已修：复刻官方 realpath（逐字符对拍）+ 全部报告化 |

| 7 | 「AIO 读不了 v4」 | 属实（AIO 0.1.5 只有 v0→v1/v1→v2/v2→v3 迁移边）。这是跨代物理边界，不是本工具能变出来的 | 明确为已知边界，界面照实提示 |

## 1. 四类修复的技术细节

### 1.1 仓库路径校验：认两种 blob 布局
- `blobs/<homeId>/<rel>`（v4 及更早）
- `snapshots/<snapId>/files/<homeId>/<rel>`（v5 起）
- 旧清单没有 `rel` 字段时，从 `path` 反推恢复目标路径（两种布局都支持）。
- 影响：恢复/校验/导出/MCP 全部恢复可用。

### 1.2 「合并模式」真合并
- 复制前把目标端 `storages/workspace.json` 原件读进内存；
- `copy_dir_merge` 复制完（含覆盖）后，先把目标原件写回，再与来源结构化合并（工作区按 path 对齐、sessionIds 取并集、目标端原登记全部保留）；
- 只要勾了「对话记录」就执行这一步，不再要求同时勾「配置」。

### 1.3 登记路径的「官方化」
官方 `dsh-workspace` 的写入路径（`mutate()`）会用
`sessionPath(id) === record.path` 过滤 `sessionIds`——只要字符串对不上，登记就被清。
而 `sessionPath` 来自 `realpathNormalize(cwd)`（Node `fs.realpath`）。
因此 Vault 现在写登记前先做同款规范化：
- `std::fs::canonicalize` + 去掉 Windows verbatim 前缀（`\\?\` / `\\?\UNC\`）；
- 与已有工作区按「规范化后相等」匹配，命中后顺手把旧记录修正为规范形态；
- **对拍证据**：对含中文+空格的目录、以及 junction（链接目录），Rust 输出与 Node `fs.realpathSync` 逐字符一致。

### 1.4 找回与报告
- 「时间机器 → 回到这个状态」以前是拿**最新**清单做补缺（名不副实），现在按所选快照自己的 `manifest.json` 恢复，恢复前照旧自动存当前状态为保险快照。
- 修复登记 / 找回对话 / 切换完成后的报告，现在会明确区分三种「看不见」：
  1. 未登记（已补登记，重启可见）；
  2. 已归档（官方默认隐藏，切「全部对话（显示已归档）」可见）；
  3. 原工作目录不存在（官方规则决定其不会显示；引导重建目录或改用「迁移」换工作区）。

## 2. 源码依据（本机实证）
- `dsh-workspace/lib/index.js`
  - L102-104：`sessionIds` getter 按 `sessionPath(id) === record.path` 过滤；
  - L173-191：`mutate()` 写回时**再次**用同一条件过滤（不匹配的登记会被永久清掉）；
  - L344-348：`initialized === true` 时不再 bootstrap；
  - L595-667：`bootstrap()` 按 cwd 分组、建工作区、补登记；
  - L700-727：`indexHeader` 要求 cwd 能 `realpath` 且是真实存在的目录，否则 `invalidSessionPaths`。
- 会话文件与目录命名：`projectKey(cwd)`（`--…--` 包裹、`~XXXX` 转义、251 截断），会话目录内用规范文件名 `session.jsonl.zstd` 或 `session.vN.jsonl.zstd`。

## 3. 升级后怎么用（同学机器 / 任意机器）
1. 安装新包（0.2.0）。
2. 打开「切换」页，选好目标环境。
3. 先点 **修复对话登记**：
   - 「已补登记 N 条」→ 重启 DSH 即可在侧栏看到；
   - 「已归档 N 条」→ 侧栏筛选切到「全部对话（显示已归档）」；
   - 「原目录不存在 N 条」→ 先重建原目录，或用「迁移」把它们迁到存在的工作区。
4. 如果是以前用替换模式弄丢的对话：在「找回对话」面板选对应那次的保险快照 → 点「找回其中的对话」。
5. 想整体回到某次备份：时间机器页选快照 → 「回到这个状态」（恢复前会自动再存一份保险）。

## 4. 明确不做的（边界）
- 不篡改官方规则：cwd 目录不存在时官方就是不会显示，Vault 只报告和引导，不硬塞。
- 不擅自取消归档：归档状态忠实迁移，只在报告里说明。
- 不反向兼容：AIO（0.1.5）读不了 v4 会话，只能让目标端自己升级格式。
