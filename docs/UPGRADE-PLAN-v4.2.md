## 1. 问题①根因复述（一句话）

切换 = 搬"显示数据"（sessions 等 9 类），没搬"运行配置"（`settings.yaml` 里的 `llm-pi-ai.providers`），
而每条会话把自己上次用的模型路由（如 `qiu005/deepseek-v4.1-flash`）记在日志里 ——
目标端没有 `qiu005` 这个提供方，也拿不到对应 API Key，于是**历史能渲染、回合跑不起来**。

已验证的修复通路（本机实证）：官方版启动时会把 home 根的 legacy `settings.yaml` 自动导入为 profile 设置，
并改名为 `settings.yaml.imported`（本机 `.dsh\settings.yaml.imported` 926 B 即是证据，含 qiu/aliy/pp 三个提供方）。
**所以"把 settings.yaml 带过去"是官方认可的合法迁移路径，不是野路子。**

## 2. 模块划分（按依赖顺序，每模块可独立验证）

### 模块 A（S1·核心）：切换可路由性体检 + 迁移后待办卡片
- 新增 `src-tauri/src/routecheck.rs`：
  - 解析会话日志（复用 `zstd_check` 的逐帧解压），只读**最后一条** `model/selection` 事件 → 得到 `provider/model`；
  - 读目标端提供方目录：目标 home 的 `settings.yaml`（如有）+ `profiles\desktop\cordis.yml` 里的 `llm-pi-ai` 段 → 得到可用 provider 集合；
  - 逐会话判定：OK（无路由记录/走默认）/ BLOCKED-缺提供方 / BLOCKED-缺凭据（凭据引用名不在目标 `.credentials.yaml` 的 refs 里，**只比对名字不读值**）/ 已归档（id ∈ `storages\workspace.json` 的 `global.archivedSessionIds`）/ 工作目录缺失（会话头 `cwd` 不存在）/ 附件缺失（日志内 `attachmentId` 计数>0 且目标无 attachments）。
  - 输出六类清单（报告 §6.3 算法原样落地）。
- 切换成功后前端弹"待办卡片"：
  - "N 条对话可直接继续；M 条需要你在目标版本里做这 3 件事：① 点对话输入框旁的模型位，把 `qiu005/...` 换成可用模型（每条一次）；② 或按下图步骤添加同名提供方并重新粘贴 Key；③ 已归档的 K 条需先取消归档。"
  - 卡片提供"一键复制排障摘要"（脱敏）。
- 验证：本机自测 —— 把 AIO 会话切到 v4lite，预期卡片列出缺 `qiu005` 的会话数。

### 模块 B（S1）：settings.yaml 纳入切换范围（可选开关，默认开）
- `switch_links` 新增处理：源 home 根若有 `settings.yaml`，复制到目标 home 根（**不是** 9 类目录，是 home 根文件）。
  - 目标已有 `settings.yaml`：先备份为 `settings.yaml.bak-时间戳` 再覆盖，保险快照同步收录。
  - 目标已有 `settings.yaml.imported`：不动它（说明官方已导入过旧配置，新文件等下次启动导入）。
  - 复制后提示："官方版将在下次启动时自动导入这份配置（会改名为 .imported），请重启目标 DSH。"
- 前端切换面板加一行说明文案：配置会带过去，**但 API Key 永远不带**（密钥环绑定），需要在目标版本界面重录。
- 验证：U-08 实验 —— 隔离副本 home 放最小 settings.yaml，启动官方版确认生成 `.imported` 且 `llm-pi-ai` 生效。

### 模块 C（S1）：切换前预检清单（pre-flight）
在现有"进程占用检测"之上补 4 项（报告 §6.2 精选，不搞满 10 项防过度工程）：
1. 磁盘空间：目标盘剩余 ≥ 源内容 ×2（已有 `check_disk_space` 可复用）；
2. 源端正在写入的会话：切换源 home 的 sessions 最近 10 秒内有 mtime 变化 → 警告"源 DSH 可能正在写入，建议先关闭源端"；
3. 提供方差集预告：切换**确认前**就跑一次模块 A 的体检（只读），把"切过去后会有 M 条对话需要换模型"提前展示，用户知情后再点确认；
4. 目标端将被删除的条目数（镜像语义预告）：列出"目标端有、源端没有的会话 N 条将被移入保险快照"。
- 验证：故意在源 DSH 打开时切换，看第 2 条是否触发。

### 模块 D（问题②）：动态跟随设计 —— "轻量守护 + 操作后自动增量"
不搞常驻文件系统监听（ReadDirectoryChangesW 在 junction 海量小文件场景容易丢事件且耗电，对小白用户是负资产），改用三层：
1. **操作后自动同步**（已部分有）：任何备份/切换/恢复完成后，自动重扫并更新缓存（v4.0 已做）；
2. **启动时增量快扫**：Vault 启动时对已接管环境做一次"mtime 比上次缓存新？"的快速比对（只扫 sessions/skills 两个动态目录的文件数+最新 mtime，不哈希，毫秒级），发现变化 → 角标提示"AIO 版有 3 条新对话、1 个新技能，点我收录"；
3. **一键收录按钮**：体检页每个环境卡片上加"收录新内容"，只做**增量**备份（新文件进仓库，旧文件不动），带进度条。
- 明确告知用户边界：Vault 不接管期间产生的对话，要在下次打开 Vault 时点一下"收录"（或切换前自动提示有未收录内容）。
- 切换前自动检查：源端有未收录的新文件 → 提示"源环境有 N 个新文件还没收录，先收录再切换？"（防止切了旧版本）。
- 验证：在 AIO 里新建一条对话 + 装一个技能，打开 Vault 看角标是否出现，点收录后切换确认新内容到达目标端。

### 模块 E（问题③）：接管兼容性专项验证 + 修复
先在本机做**受控实验**（每个都可回滚）：
1. 接管状态下逐项测 DSH 功能：新建对话 / 发送消息 / 加载技能 / 唤起 memories / undo / 归档取消归档；
2. 记录哪些报错，对照三类嫌疑定位：
   - skills 路径分裂（官方版读 `~/.agents\skills`，被接管后 `<home>\skills` 变 junction）→ 方案：把 `~/.agents\skills` 也纳入可选接管，或接管时在 `<home>\skills` 里放指向共享库的说明文件；
   - 实验性 preset 残留（`.agent-presets` 里 anchored-standard 指向 gateway 路由）→ 体检中标注"该预设在当前版本可能不可用"；
   - AGENTS.md 注入块被某些版本当异常 → 检查注入格式，改为更保守的追加。
3. 产出"接管兼容性清单"文档，UI 接管按钮旁加"接管后若有功能异常，点这里自助排查"。
- 原则：**不是"接管必然报错"，而是三类已知边界**，逐一定位修掉。

### 模块 F（S2）：一键回滚本次切换
- switch-backups 已有保险快照；补：
  - 切换快照生成 manifest（文件数+哈希）；
  - 前端切换结果页加"后悔药：回滚到切换前"按钮 → 调 restore 逻辑把保险快照写回（凭据文件硬跳过）；
  - 保险快照升级收录范围：9 类 + home 根 `settings.yaml`（若本次带了配置）。
- 验证：切换 → 回滚 → 比对目标端文件数与切换前一致。

### 模块 G（S2·顺手修）：扫描警告文案修正（P-15）
- `merge_save` 保留旧发现时，先对旧路径做一次 `Path::exists()` 复核：
  - 存在 → 警告改为"本次浅扫未覆盖（路径仍在，深扫可确认）"，前端标灰但不渲染成"可能已删除"；
  - 不存在 → 才写"可能已移动或删除"。
- 会话版本统计修正（P-16）：按文件名 `session.v3/v4` 分档计数，不再把 v3 并入 v4。

### 模块 H（S3·明确边界）：切换语义文案
- 切换确认弹窗固定文案（报告 §6.7）：
  "本操作会用【源环境】的内容**替换**目标环境的所选内容；目标端多出的 N 条对话会先存进保险快照（可回滚）。API Key 不随切换走，模型提供方需要时在目标版本重录。"
- 恢复/备份/切换三个入口各加一行"本操作覆盖范围"小字说明（P-05/P-13）。

## 3. 明确不做（本期）与理由

| 报告建议 | 本期不做原因 |
|---|---|
| 会话级导出包 `.dshpack`（P-30 完整方案） | 工程量大（约等于重写半个切换链路），先做"整环境切换+体检+待办"让同学场景跑通；会话级转移列入 v4.3 |
| attachments 迁移（P-04） | AIO 专属目录，官方版没有对应读取逻辑的证据，搬过去也可能不认；先在体检里标注"该会话含 N 个附件，图片可能裂" |

| profiles 合并算法 | 官方导入机制已够用（settings.yaml 路径），手写 yml 合并容易写坏配置 |

## 5. 给同学的关键答复（随新版一起发）

- 上次"能看不能聊"的根因：切换没带模型提供方配置（qiu005/gpt020qiu 是 AIO 自定义的），新版会把配置带过去并逐条体检对话；
- 已经发生的事怎么救：官方版里打开那些对话 → 点输入框旁的模型名 → 换成 DeepSeek 官方模型即可继续（每条一次）；或在设置里添加同名提供方并重录 Key；
- 新版切换完会有一张"待办卡片"直接告诉你要做什么，不用再猜。
