| 6 | 隐患：恢复时空壳凭据覆盖目标真实凭据 | `run_restore` 对 `.credentials.yaml` 无任何特殊跳过；空壳（10 字节）若覆盖目标真实凭据（478 字节有 Key 引用），用户 Key 丢失 | 我们（安全漏洞，必须堵） |

## 红线（不可违反）

- 凭据安全：绝不读取/输出/转存 API Key 明文；`.credentials.yaml` 禁上传 GitHub/云盘；恢复/切换**默认跳过**凭据文件，防止空壳覆盖真实凭据。
- 数据不丢：旧备份不可被覆盖；切换/恢复前必须有保险。
- 新手友好：自动扫描优先，少让用户选文件夹；操作有进度反馈。
- 不靠固定路径：扫描/识别算法要能适应任意安装位置、各种封装版。

## 技术决策记录（已查证）

- **preset 默认不跨版本带**：`anchored-standard` 等实验性 preset 是社区版 gateway 路由的产物，官方版不认识会报错。默认关闭 `include_presets`，用户明确需要才勾选。配置里的 `guard/storages/rollbacks/undo-snapshots` 等基础配置仍随 `include_config` 走（这些跨版本安全）。
- **凭据跳过而非迁移**：密钥环绑定机器+用户上下文，文件搬过去也解密不了（03.3 已证实）。跳过是唯一能保证“不覆盖掉目标真实凭据”的做法。用户要 Key 就在目标版本界面重录（方案 A，04.2）。
- **合并而非替换缓存**：扫描是探测性操作，任何一次扫描都可能因权限/深度/超时漏掉；历史发现记录比当次探测结果更可信。消失路径保留+标注，由前端标灰，不静默丢。
- **操作日志脱敏**：只记操作类型、涉及的环境 id/标签、文件数、字节数、成功/失败、错误摘要；绝不记文件内容、不记凭据、不记 Key。导出 markdown 供排障。
